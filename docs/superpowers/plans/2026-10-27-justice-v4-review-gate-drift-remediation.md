**Single ordered commit lifecycle (Task 4):**

Marking a local dispatch complete or appending unverified V2 journal bytes never substitutes for protected publication.

**Crash windows/tests (Task 4):** (A) prepared but uncommitted dispatch = recover matching publication **without Host dispatch**; (B) committed dispatch but no verified Host claim/response = await evidence/SUSPEND, **no automatic physical relaunch**; (C) private \`STAGED\` but no RESPONSE_STAGED event = verify \`readExact\`, publish the identical evidence event once; (D) staged witness event but no private bytes = BLOCK; (E) verified RESULT_COMMITTED but private still STAGED = reconcile by \`markResultCommittedPendingApply\` after verifying bytes/event, no reparse-induced duplicate effect; (F) verified OUTCOME_APPLIED but private still pending = \`markFullyApplied\` exactly once. Duplicate same response+attempt = reuse verified event, no double Core apply; conflicting digest, wrong generation/attempt/callId, stale phase, corrupt private installation, quota exhaustion and missing trust root = SUSPEND/BLOCK, no extra generation/round, no mutation, no Plan CLEAR. Persistent identity is from the witnessed operation and private ledger; process-local \`sessions\` or untrusted workspace recovery cannot alone authorize post-restart worker response. An absent durable authenticated call claim cannot be fabricated on restart.
