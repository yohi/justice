## B. Architecture decision / constructive impossibility witnesses

**Counterexample 1 — legitimate direct release:** [`.github/workflows/release.yml`](https://github.com/yohi/justice/blob/c428041dfb5779b6b6dc8db7bf14928225a00373/.github/workflows/release.yml) checks out a release tag, builds JS and native code, uploads an artifact, publishes to GitHub Packages via `npm publish --ignore-scripts`, and uploads a release asset. These are real *consumer routes*, although a local JSONL observation is **not automatically** an accepted B2 authoritative snapshot. No source evidence demonstrates their mandatory Gateway switch.

**Counterexample 3 — irreversibility:** acceptance in Postgres cannot undo a GitHub repository update, network command, npm publish, human-visible release, mutable worktree or external process effect. Merely appending an outbox entry afterwards cannot make such an effect atomic with acceptance. Without authoritative consumer/publisher cutover **`CURRENT_TOPOLOGY=STRUCTURALLY_INCOMPATIBLE`**.

**Counterexample 4 — timing:** `t_check < t_expiry < t_db_linearization` is allowed by a pre-COMMIT check; an asynchronous revoke issued at t0 but imported to DB at t2 permits a t1 commit under stale epoch. Signed preflight time, PostgreSQL `now()` and ACK timestamps do not certify the real COMMIT instant. If R11 demands both immediate source-time revocation and a fully attested commit instant, one DB transaction and independent asynchronous service are insufficient *without an additional synchronous serialization/attestation protocol*. This proposal does not pretend one exists.

**Current verdict:** `ARCHITECTURAL_REDESIGN_REQUIRED` and `STOP` before any authorized operations. **Conditional alternative C1** below defines what needs to become provable, not a claim that it has been achieved. Rejection of C1 leads to C2: leave Justice's original Git/CI release lifecycle authoritative for *ordinary product builds only*, and specify R11 accepted workspace/effect namespace separately with *explicit no-bridge/no-production adoption*. C2 MUST NOT advertise accepted B1/B2 source or phase authority over the ordinary product lifecycle. Neither can bypass future independent review and normative adoption.

## C. C1 — minimal proposed trust boundary and authority grammar

```
Human signed IAB/HSA authority --verify-only--> Independent Broker + restricted operation handler
Separate signer / revoke sequencer / time issuer --> bounded independent proofs + fence decision
Actor subtree (no creds/privileged FD/raw egress) --> private, nonpublishable stage
Broker + DB-only writer -------------------------> single primary, DB-owned immutable bytes + receipt + head/accepted_seq
DB Gateway (fresh current or explicit historic pin) --> sealed, verify-at-use snapshot --> restricted builder/verifier
Builder independent release attestor -----------> effect authorization / external publisher (separate terminal event)
Independent append-only prefix witness <--------- ACK high-water and signed final receipt custody
NO raw Git/worktree/JSONL/CI/npm direct route => R11 'accepted' semantics
```

Authority identity: `(authorityDomain, scopeId, phase, attemptIndex, baselineId, branch, term, acceptedSeq, headDigest, formatVersion)`. `headDigest = SHA256(canonically encoded full manifest)` containing path bytes, file mode, symlink target, all content digests and retained source/import closure. `contentDigest = SHA256(exact immutable bytes)`. `EAF` additionally binds *package+lock, dependency integrity, compiler/flags/native tooling, generated JS closure, profile and negative controls*; **headDigest does not stand in for EAF**, and a Git commit SHA is not a full content digest. Stage is never an authoritative output.

**CURRENT read** means a request-scoped consistent primary snapshot acquired after the consumer's invocation; it must include latest fenced `acceptedSeq`, `headDigest`, full immutable bytes and committed receipt; cannot use a pre-ACK transaction, replica, CDN or unbounded cache. **HISTORIC_PIN** means a separately authorized `(scope,term,seq,headDigest,receiptDigest)` as an explicitly historical artifact; it does *not* imply current head or a live phase grant. For source-controlled CI, the raw Git commit is an input locator only: a deterministically matched, accepted manifest digest/seq + compiler/dependency graph + phase purpose must be enforced **before build** and again at **use**. A match merely by branch or tag is forbidden. An ACK or witness loss denies CURRENT claims. Read or proof unavailable ⇒ `UNKNOWN/BLOCKED+STOP`; verified unauthorized bypass ⇒ `REVOKED+STOP` where R11 requires, not merely a benign error.

**Consumer census** is `03_CONSUMER_EFFECT_TRUST_CENSUS.csv` (named observed edges, plus explicitly `UNCENSUSED/OPEN` vectors). The C1 cutover must include product consumers or show their effects are formally separate and incapable of contaminating any accepted R11 namespace. A root-of-trust census must cover future legitimate readers, operators, admin, backups, mirrors, host, workflow_dispatch, GitHub release and third-party package consumers; documentation must not claim closure from the enumerated sample. Compiler/linker, dynamic imports, transpiler, native artifact, `.node` addons, package hooks and `postinstall` are relevant bytes/effects.

## D. Accepted transaction contracts (logical schema; not DDL)

| Domain record | Required identity/constraint | Writer/read contract |
|---|---|---|
| `Authority` | `(scopeId)` locked row; `headDigest, acceptedSeq, revokeEpoch, physicalTerm, baselineId, phaseAttempt` | DB-only writer; current reader uses single consistent snapshot, no replica |
| `Content` | `(digest, length, byteFormat)` immutable, exact bytes DB-owned; full root and chunk membership in one COMMIT | no independent S3 blob/GC in candidate A |
| `Reservation` | `(scope,phase,attempt,opId)` unique, stable `attemptSeq`, signed prepare digest, state `PREPARED/ACCEPTED/ABORTED/IN_DOUBT` with canonical terminal link | `PREPARED` durable before *any* private stage operation; IN_DOUBT blocks closure |
| `Operation` | `(scope,phase,attempt,opId,requestDigest)` unique, `beforeRoot,afterRoot,authDigest,stageDigest,headSeq,outcome,term,receiptDigest` | identical replay returns identical outcome after term/prefix reconciliation; different binding => conflict STOP |
| `Event` | locked transactional `attemptSeq` per phase, type, opId, predecessor receipt digest, canonical bytes, event digest | separate acceptedSeq (only ACCEPT), terminal one-per-reservation closure |
| `Revocation` | independent signed `sourceEventId,issuerOrder,issueTime,effectivePolicy,epoch,scope,DBFenceSeq` | ordered trusted ingestion; duplicate idempotent, missing order => STOP |
| `Publication` | `receiptDigest,externalEffectId,artifactHash,publisherActor,terminalState,outcomeEvidence` | *separate* from DB accepted transaction; external effect never described as DB-atomic |
| `AckWitness` | `(scope,physicalTerm,acceptedSeq,headDigest,receiptDigest,prefixChainDigest)` monotonic nonrollback signed by non-DB custodian | must be confirmed before final accepted ACK; loss/unknown blocks recovery |

Transaction preparation: authenticate true ingress origin (A1 remains not proven), phase/scope/branch grant and immutable IAB, signed protection policy, signed independent revoke/time evidence; reserve unique opId+attemptSeq under fenced leader and durably insert `PREPARED` before enabling any private stage. If any precondition or trustworthy time guarantee is unknown, deny and persist no externally visible effects. The actor cannot choose its own idempotency scope or self-sign proof.

**Conditional acceptance transaction T** (never allowed until E/F/G proof obligations below): on the only physical fenced primary, `BEGIN` with isolation/serialization contract and durable WAL policy; lock `Authority` for scope, Reservation and active authenticated revoke/term fence; require immutable `beforeRoot == currently committed head`, `grantBaselineId`, `(phase,attempt,opId,requestDigest)` and authorized path/hunk/mode/symlink/protected-root delta; full stage root measured from a frozen, writer-impossible snapshot; append required DB-owned exact bytes; guard increment `acceptedSeq` using **row update**, not `nextval()`; set terminal `ACCEPTED`, immutable accepted receipt bytes, head and receipt/event links **inside the same transaction**; COMMIT. This is one atomic DB visibility point **only for these DB records**. On `40001` abort, redo whole transaction with fresh authority/epoch/time and remeasurement; never reuse a preflight proof. On network loss or ambiguous COMMIT ⇒ `IN_DOUBT`, lookup exact opId on certified term+prefix, no blind replay or predicted success.

**Doubly important:** `COMMIT` cannot include a post-commit separately signed receipt or network ACK. If the R11 `externalReceiptOrAtomicEquivalentProof` demands independently externally durable proof **at the same linearization point**, C1's unadorned DB-only ACID **does not satisfy it**. Candidate C1 must pick *one* rule, Owner/normative adoption pending: (a) replace the acceptance protocol with an independently verifier-trusted append-only authoritative transaction service that stores exact bytes and proof in its **single atomic domain**, or (b) explicitly revise normative R11 to define a two-threshold `DB_COMMITTED_INTERNAL` then `EXTERNALLY_SEALED_VISIBLE` protocol and prove no consumer/ACK observes the unsealed intermediate. Choice (b) is a genuine normative delta, not equivalence established here. Without adopted change and independent proof => **STOP**, do not label final receipt ACCEPTED.

### D1. PREPARED / terminal ledger reconciliation

* `attemptSeq` reserves every operation, including rejected/staged/aborted; it is monotone and may be allocated only by the fenced transactional row counter, with every reserved attempt having exactly one terminal `ACCEPTED` or independently verified `ABORTED` record. A stranded record is `IN_DOUBT`, not retrospectively ABORTED by timeout. Inbound requests rejected **before** a durable reservation have no attemptSeq and have a separately bounded denial record; they do not create gaps.
* `acceptedSeq` advances **only** when accepted receipt/bytes/head commit together. It is gap-free among accepted events, not equal to attemptSeq. For each accepted ordinal `k`, predecessor accepted record `k-1` and content-root inclusion proof exist. Accepted sequence increments by +1 under the locked Authority row; abort never consumes acceptedSeq.
* **Phase close predicate:** for every reserved attemptSeq `i ∈ [1,lastAttemptSeq]`, exactly one contiguous durable terminal exists (`ACCEPTED` or `ABORTED`) with consistent final opId and proof; no `PREPARED/IN_DOUBT` anywhere; acceptedSeq exactly enumerates all accepts; current full root matches last accepted head; no mutable scope writer, independent PhaseSeal covers terminal-set digest and final root. A phase close cannot silently skip a missing/duplicated attempt or infer abort from an absent ACK. Negative result (tombstone) itself must be independently reconstructible.
* `OP_ABORTED` requires trusted no-authoritative/no-external-effect proof. If external effect may have happened => `IN_DOUBT+STOP`, not safe abort. No later `acceptedSeq` advancement is allowed to conceal an in-doubt earlier phase reservation.

## E. Trusted time and revoke source order: contradiction-preserving contract

**Contract choice not yet approved:** Revocation must carry two distinct instants: `sourceIssuedAt` (authenticated source decision) and `fencedEffectiveAt` (commit-order point guaranteed to be enforced), plus source ordinal and importer DB commit/receipt ordinal. **Never infer** `sourceIssuedAt == DB fence effective` from a message timestamp. A revocation authority issuing a safety-effective instant at t0 without synchronous, irrevocable fencing of all acceptance is incompatible with a t1 database acceptance before delayed ingestion at t2. A delayed, reordered or missing event => revoke freshness uncertainty ⇒ all affected commits and host external effects STOP, including producer/consumer readers where current authorization is required.

Two explicit options (both conditional):
1. **Strict source-time revoke**: a *single mutually exclusive acceptance/revocation serialization authority* must bind a permit and revoke decision at the same linearization point, including cross-system failure and worst-case delivery. A DB epoch row update *alone* is inadequate. No design of such a service is established; current choice is `UNKNOWN/BLOCKED+STOP`.
2. **Fence-effective revoke**: issuer does not claim external revoke is effective until all acceptance/effect enforcers have fenced the previous epoch, acknowledged and committed the epoch; until then the source has state `ISSUED_NOT_EFFECTIVE` and commits MUST STOP when uncertainty is detected. Owner must explicitly accept the changed semantics and residual blackout; it cannot pretend issued-time instant protection. Missing fence ACK or known revocation lag remains STOP, not eventual-consistency success.

**Time contract:** `notBefore <= realLinearizationInstant < expiresAt` applies to accepted operation, and host effects have independent per-effect boundaries. Proof must bound `[T_lower,T_upper]` for the *actual durable linearization instant*, not only preflight. Signed issuer clock time has age, uncertainty, anti-replay, issuer identity and latency; DB `now()` is transaction-start, `clock_timestamp()` is untrusted as an independent attestation, and a timeout or commit ACK timestamp is not retrospective attested COMMIT time. Merely checking `T_preUpper < expiry - epsilon` is not enough if commit waits past epsilon or a cancelled statement actually commits. A valid acceptance requires a provider-guaranteed worst-case stop-before-commit mechanism with independent bound `T_commitUpper < expiresAt`, `T_commitLower >= notBefore` *and* a revoke-serializable fence; this design has NO such confirmed primitive. Unless a future protocol can prove these bounds, `C1.COMMIT_ALLOWED=false`, and retime/rebind the contract through formal R'/D'/P' revision instead of faking proof. Historical accept before expiry is valid when genuinely attested; later expiry does not alter history.

Time/revocation negative classes: expired known ⇒ `EXPIRED/STOP`; no clock/ordinal proof ⇒ `UNKNOWN/BLOCKED+STOP`; independently established public unauthorized side effect ⇒ `REVOKED+STOP`. R11's existing typed distinctions remain unchanged.

## F. Independent record proof, ACK, backup and primary fencing

**DB exact atomicity:** the commit includes canonical immutable `AcceptPublishSeal` *bytes* (or type-approved row serialization), associated exact source content, digest, full root, seq, epoch, terminal and fenced term. This is a transaction witness *within DB custody*; a DB-admin can rewrite/restore outside the ordinary role boundary. The custodian/notary's separate signature after COMMIT is a second effect. A detached signer pre-signing a candidate does not certify successful COMMIT. Therefore the current externally attested R11 requirement cannot be assumed fulfilled by DB transaction presence alone.

**Conditional two-threshold publish alternative** (requires formal revision): DB commits candidate and blocks Gateway-visible `ACCEPTED` until independently durable external receipt over `(scope,term,seq,headDigest,dbReceiptHash,prefixHash)` is obtained. A second transactional status marker may release visibility, but it is NOT atomic with the first DB COMMIT, and recovery must reconcile orphan/seal. No later op may consume a hidden predecessor. Never ACK until seal + independent ACK-prefix witness; absence/timeout is `IN_DOUBT+STOP`. Gateway cannot return a head from a restored or unsealed DB while witness mismatch is unresolved. This is a *design fork* needing independent adjudication of R11's `atomic-equivalent` clause, not a unilateral assertion of compliance.

**ACK invariant:** if client has received `ACK(opId,term,seq,hash)`, every later certified `READ_CURRENT` must return a head with a recoverable accepted prefix containing `(term,seq,hash)` (unless explicit subsequent accepted head supersedes). A successful DB COMMIT **without final ACK** is not permission to assume abort. `AckWitness` monotonic high-water must durably precede final ACK and be controlled outside primary backup/restore domain. On ambiguity, STOP; never fabricate an ACK.

**Disaster restore:** restored DB shall remain isolated from Gateway/actor/new writes until an authorized recovery verifier proves (i) all independently ACK-witnessed prefix records and exact immutable bytes exist in restored+replayed WAL, (ii) continuous accepted/attempt terminal history, (iii) no issuer/revocation regression, (iv) monotonic term, (v) old primary is physically unable to write or serve readers, (vi) current leading head is >= ACK high-water, (vii) provenance and signatures validate. A term column is only *logical*: power/fencing, storage exclusivity, credential/route revocation, quorum/STONITH-equivalent and independent operator attestation are separate physical requirements. Without independent physical fence proof, **zero automatic failover, STOP indefinitely**. Replica/backup/CDN cannot be CURRENT authority in C1. Future implementation must document sync durability mode and storage-loss adversary model; PG settings alone are not evidence now.

## G. Materialization-to-use and external effects

**Immutable materialization procedure:** authorized Gateway `READ_PINNED` or `READ_CURRENT`, verify manifest/receipt/seq/term/freshness and full byte hashes, materialize to newly created *isolated copy* with no actor-write path, no writable bind mount/hardlink, no mutable directory, no open write FD and no privileged alternate writer; freeze file tree identity and use closed FD / immutable read-only mount snapshot / equivalent audited isolation. Compute actual byte/mode/symlink/dependency graph hash *in the build/host namespace at the last possible pre-use boundary*, use exactly that snapshot for compile/load or stop. A digest proof for an earlier copy is insufficient. Changes in dependencies, lock, toolchain or transitive native binary mean a new EAF; launch/load may require an additional use-bound check. Do not reuse old HEAD as CURRENT just because its digest remains available. If absence of concurrent writes cannot be proved => STOP rather than post-use detection.

**Remote effects:** Git write, release-please, package publish, GitHub release asset, arbitrary network command, host/export and children are *not* enclosed by DB commit. Independent effect enforcer must gate each before network/launch, bind to exact accepted+phase and signed separate effect authority and idempotency key; external service may not provide exactly-once idempotency or compensating unpublish. Publication state is `NOT_STARTED`, `PREPARED_NO_EFFECT`, `ACKED_WITH_PROVIDER_RECEIPT`, `IN_DOUBT`, `FAILED_VERIFIED_NO_EFFECT`; unknown provider outcome blocks retries and phase close. If the requirement instead is atomic commit+public npm publish in one indivisible transaction, it is **not satisfiable** by C1 and must be redesigned. Host R11 remains NO RUN until A1 H0/G1/G2 and independent RA+ACTIVATE, regardless of publication model.

## H. Named trust computing base and refusal criterion

The **TCB** includes: isolation kernel/container runtime+root operator (process, FD, namespaces, mounts, seccomp/LSM, devices, cgroups); network policy enforcement+egress proxy; physical primary/storage/WAL/admin+backup operator; Broker/Gateway binaries+signing identities; independent human grant signer, issuer/root/key custody, revoke sequencer, attested time source; accepted head+ACK high-water custodian; CI builder/binary signer, GitHub org/repo admins/action runners, external package publisher provider, authoritative consumer/host loader, review verifier and audit log operator. Solo Owner may hold several administrative duties, but actor compromise must not be able to impersonate the higher authorities. Treat admins/custodians as *trusted or explicitly excluded security adversary classes*, not as secretly controlled by app RBAC; untrusted-OS-root attacker breaks proof. List is concrete design actor categories, not verified deployment identities.

At each runtime root, name whether an actor can create a child, inherit FD (`FD_CLOEXEC` alone not sufficient against all leaks), receive `SCM_RIGHTS`, bind mount, use `/proc`/`ptrace`, docker.sock, uid/capability escape, write Git refs, control CI secrets/workflows, run lifecycle scripts, invoke GitHub API/npm provider or open a raw protected network socket. Enforcer must deny by OS/platform policy *before effects*. On an unknown edge, stop initial phase authorization until it is statically specified and later empirically verified under separate authorization. The required next design object is a complete implementation-facing trust graph with credential principal IDs, negative effect capability tests and a maintained diff-based consumer census.
